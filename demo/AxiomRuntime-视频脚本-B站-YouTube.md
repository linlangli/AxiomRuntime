## 0:00–0:35 冷开场

**画面**：黑底白字打出你某次真实翻车的时间，然后切到 502 报错截图。

> 上个月有天下午，我正改一个 bug，中转站突然 502。
>
> 我手上开着两个东西：Claude Code 和 Codex。要换到备用中转站，Claude Code 这边得改 `ANTHROPIC_BASE_URL`，Codex 那边得去动 `config.toml` 和 `auth.json`——两套完全不一样的配置。改完发现 Codex 还是走老的，又排查了十几分钟，最后发现是全局 `auth.json` 里的 key 优先级更高。
>
> 二十分钟没了。那天晚上我就开始写这个东西。

## 0:35–2:10 三个痛点

**画面**：素材 D — 分屏对照两套配置文件，光标在不同字段间跳。

> 我遇到的问题其实是三个。
>
> **第一个，换中转站要改两处。** 这两个 CLI 的配置方式完全没有交集，一个吃环境变量，一个吃 toml 文件加一个 json。手动改不但慢，还容易改一半忘一半。
>
> **第二个，不知道烧了多少钱。** 中转站基本不给你账单细节，本地也没有汇总。我经常是月底看余额突然少一大截，但不知道是哪个模型、哪个项目吃掉的。
>
> **第三个，人不在电脑前就干不了活。** 这个是后来才意识到的。很多时候我知道要改什么，就一句话的事，但人在外面，只能等回去。
>
> 前两个是效率问题，第三个是我最后决定动手的原因。

## 2:10–3:20 它是什么 + 装

**画面**：素材 E — `npm install` → `ai --version` → `ai setup` 引导流程。

> 它叫 AxiomRuntime，npm 包名是 `@offerpilot/axiomruntime`，装完之后注册的命令是 `ai`——**这三个名字不一样，搜的时候注意**。
>
> ```
> npm install --global @offerpilot/axiomruntime
> ai setup
> ```
>
> 要 Node 22.19 以上，20 跑不了。如果 npm 给你报 `EBADENGINE`，别当普通警告忽略，那个状态下装出来的 CLI 有问题。
>
> 还有一点得先说：命令名是 `ai`，两个字母，很容易和你机器上已有的东西撞名。装之前 `which ai` 看一眼。
>
> 另外它不装 Claude Code 也不装 Codex，不替你出 token。它只管理你已经有的这些。

## 3:20–4:40 配 provider，以及一个设计取舍

**画面**：素材 F — `ai provider list` 三个 provider 卡片，level / mode / model 都在。

> 配置就是加几个 provider，给每个定一个 level。level 1 是默认，挂了往下走。
>
> 这里有个我一开始做错的地方，值得说一下。
>
> **最早我是直接改 `~/.claude/settings.json` 的**，把 baseUrl 和 key 写进去。跑通了，但很快发现问题：这是用户自己的配置文件，我往里面写东西，等于污染了他的环境。而且你直接敲 `claude` 不经过我这个工具的时候，配置还是被我改过的状态。
>
> 后来改成：每次启动生成一个**临时** settings 文件，用 `--settings` 传给 Claude Code，跑完就没了。你的 `~/.claude/settings.json` 我一个字都不动。
>
> Codex 那边同理，用 `-c model_provider=` 只对这一次子进程生效，全局的 `auth.json` 和 `config.toml` 保持原样。你想绕过我直接敲 `codex`，行为完全不变。
>
> 这个取舍我觉得是对的：**一个管配置的工具，不应该让你没法不用它。**

## 4:40–6:30 降级现场（核心段）

**画面**：素材 B + C — `ai status` 全屏，先停在 level 1 的 `health:error` 和 502 那两行，再跑 `ai use claude`。

> 这段是我最想给你看的。
>
> 我把 level 1 那家故意配坏了。`ai status` 会真的发请求刷一遍健康度，你看第一家：`health:error`，底下写着 `GET .../v1/models failed with 502 Bad Gateway`。第二第三家 ready，后面跟着各自可用的模型。
>
> 现在直接 `ai use claude`——
>
> 【停一下让画面走完】
>
> 它跳过了坏的那家，起了第二家。我一个配置都没改。
>
> 这里其实是**两层不同的机制**，我得说清楚，不然你以后遇到会觉得行为不一致：
>
> **第一层是启动前筛。** 健康检查已经知道 level 1 是 502，所以它根本没被列进候选，直接跳过。
>
> **第二层是跑起来之后挂了再换。** 如果一家健康检查是通的，但真跑的时候进程非零退出，它会打出 `Provider xxx unavailable, fallback to yyy`，然后接着试下一家。
>
> 这两层是分开的。第一层管"看起来能不能用"，第二层管"实际跑得起来吗"。我一开始只做了第一层，后来发现健康检查过了但真实推理失败的情况也不少，才补的第二层。

## 6:30–7:30 用量

**画面**：素材 B — `ai status` 停在 token 数和占比那几行。

> 用量是顺手做的，但后来变成我最常看的。
>
> 它记的是 provider **真实返回的** usage，不是估算。Codex 那条链路是本地起一个 OpenAI 兼容的代理透明转发，把返回里的 usage 记下来，不改 Codex 本身的请求和响应。
>
> 有些模型只给 token 不给费用，这种才会按你自己配的价格表估。**估的和实测的我分开标，不混在一起给你一个假精确的数字。**

## 7:30–9:30 Telegram

**画面**：素材 A + G — 手机真机录屏。发消息 → 进度消息实时变化 → 出 diff → `/usage`。

> 最后这个是我自己用得最多的。
>
> 【手机画面】我发一句话过去。你注意看这条消息——它**不是**一条条刷新消息，是同一条消息自己在变：现在什么阶段、在调什么工具、回答预览。
>
> 这个地方我踩过坑。最早我想做成逐 token 更新，像网页版那样一个字一个字出。结果 Telegram 的编辑接口有频率限制，直接 429，而且重试的时候还会重复执行。后来改成按完整的 JSON stream event 合并，默认至少 1500 毫秒更新一次。**没那么炫，但不会挂。**
>
> 其他能用的：`/pin` 固定关键上下文，`/usage` 看这个会话花了多少，可以传文件和图片，`/terminal` 直接跑命令——高风险命令会强制让你在 Telegram 里点确认。
>
> 多个 bot 之间配置是隔离的，我自己开了几个对应不同项目，各自有自己的工作目录。

## 10:10–11:20 接下来做什么

**画面**：抽象动画或静帧字卡都行，不需要产品界面。

> 这个东西现在是个管 provider 的开关，但我想做的不止这个。我最终想要的是一个**用得越久越懂我的运行环境**。
>
> 两件事在做。
>
> **一个是记忆。** 你们有没有这种感觉：每开一个新会话都要重新交代一遍——这个项目用 pnpm 不用 npm、接口都在 `src/api` 下、那个 legacy 目录别动。说到第二十遍的时候会有点崩。
>
> 我想让它自己记住，而且**分层记**：关于我的习惯是一层，关于这个项目的规矩是另一层，这次临时说的过期就清掉，不要全糊成一锅。
>
> 但记忆这事我有个原则：**你得看得见它记了什么，能改、能删、能钉住。** 不是它在背后偷偷往上下文里塞东西，然后你都不知道它为什么突然这么回答。这个原则如果做不到，我宁可不上这个功能。
>
> **另一个是技能沉淀。** 你每周都要做同一套操作：拉分支、跑测试、看哪个挂了、改、提 PR。流程完全一样，但每次都得重新跟它说一遍。
>
> 我想让它到第五次的时候自己开口：这个流程我见过四次了，要不要存成一个技能，下次一句话就能跑。
>
> 同样，**不是它觉得自己学会了就直接用。** 得先拿过去那几次的记录回放一遍，确认真能跑通，再来问你要不要启用。出问题能一键退回去。
