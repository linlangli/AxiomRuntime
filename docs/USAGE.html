通过 npm 安装

node --version
npm install --global @offerpilot/axiomruntime
ai --version
ai setup

npm 包名是 @offerpilot/axiomruntime，安装后注册的可执行命令是 ai。需要 Node.js 22.19.0+。

如果 npm 显示 EBADENGINE，请先升级 Node.js 再重新安装，不要继续使用警告状态下安装的 CLI。

ai --version 无副作用地验证安装；ai setup 初始化 Runtime，并可在确认后安装缺失的 Claude Code/Codex。

全局安装可以由 root 完成，但日常执行和常驻服务应使用专用非 root 用户。root 下请求 Claude auto/bypassPermissions 时，Runtime 会安全约束为默认权限并告警，不会传递 --dangerously-skip-permissions。

brew tap linlangli/axiom https://github.com/linlangli/AxiomRuntime.git
brew install linlangli/axiom/axiomruntime
ai --version
ai setup

Homebrew Formula 复用同版本 npm tarball并校验 SHA256，固定使用 Homebrew node@22。Tap 名保留 linlangli/axiom，首次添加时必须提供实际的 GitHub URL。已有旧 GitLab Tap 的用户先更新 remote：

git -C "$(brew --repo linlangli/axiom)" remote set-url origin https://github.com/linlangli/AxiomRuntime.git
brew update

维护者发布与 CI 配置

源码仓库为 linlangli/AxiomRuntime。原 .gitlab-ci.yml 保留；GitHub 托管 runner 负责测试、门户构建与 SSH 部署，无需在生产服务器安装 Actions runner。branch push 和 PR 执行完整测试及前端类型检查，默认分支测试成功后部署门户；v* tag 单独触发 npm 发布。

在 Settings → Environments 中配置 portal-production，仅允许 main branch。Variables 包含必填的 PORTAL_SSH_HOST；可选的 PORTAL_SSH_USER、PORTAL_DEPLOY_ROOT、PORTAL_HEALTH_URL 分别默认 axiom-portal-deploy、/srv/axiomruntime-portal、https://axiom.offerpilot.life/。Secrets 包含 PORTAL_SSH_PRIVATE_KEY_B64 和已核对主机公钥的 PORTAL_SSH_KNOWN_HOSTS。部署按顺序执行，健康检查失败恢复上一 release。

npm-production 仅允许 v* tag，无需 npm Secret。在 npm 包 @offerpilot/axiomruntime 的 Settings → Trusted Publisher 创建 GitHub Actions connection：owner linlangli、repository AxiomRuntime、workflow filename publish.yml、environment npm-production，仅启用 Allow npm publish。GitHub 通过 OIDC 获取短期凭证并生成 provenance；workflow 使用 npm@11.11.0，只有 npm job 有 id-token: write。GitLab variables 不随 Git 迁移，门户 SSH 凭证需重新注入；原 GitLab CI 继续使用原有 NPM_TOKEN。

双击 发布.command 或执行 npm run release 打开发布助手。助手使用 gh 检查登录及发布 workflow，在临时目录合并远端 main，安装根目录与前端依赖并运行完整测试，确认后推送 release commit 与 tag，等待 Publish npm 结果。npm 信任连接必须提前配置，助手不能通过 GitHub API 读取 npm 端状态。如果 npm 显示 Pending validation，须在页面给定截止时间前完成一次获准的新版本发布；仅保存连接不代表发布认证已经验证。tag 提交必须属于默认分支，版本必须与 package.json.version 一致。Homebrew 单独同步 npm latest 的 tarball 与 SHA256。Git 历史迁移应先备份本机 refs；未提交修改、GitLab Issues、CI variables 和 artifacts 不包含在 Git push 中。

向服务器开放图片 API

按引导连接服务器

「接入测试 → 实际调用工作台」支持对话、Responses、向量、图片生成/参考图上传编辑、隔离工作区 Agent，以及 tools 注册工具执行。凭证仅用于本次本机或公网请求，不保存；真实调用会产生费用，响应限 40 MiB。公网授权调用成功且响应符合协议才完成第 5 步；配置变化后验证失效。当前工具只提供 runtime.status 与 providers.list，请求 POST /v1/tools/execute，请求体为 {"name":"runtime.status"}，不执行任意 Shell 命令。

「本地配置 → 工具配置」可备份并持久保存 Claude 用户连接，保留其他字段；「消息接入」支持 Bot 启动、停止、重启、删除配置（保留数据库与日志）。「运行记录」与「用量统计」提供完整历史分页、CSV/JSON 下载及每 2 秒实时刷新，内容为安全字段投影；大量历史仍需全量解析文件。SSH 连接参数进入快照，但专用私钥、主机信任、请求计数、部署验证证据不进入快照；恢复 SSH 配置前需断开隧道并关闭自启。

步骤卡片展示准备状态并可点击跳转；部署方式以选项卡片选择，下方展示连接路径与自动上游。日志、重启和停止收在「服务详情与管理」，隧道断开收在「连接日志与断开操作」，首次密钥准备说明可展开查看。窄屏下卡片与表单自动纵向排列。

旧版启动的 Bot 若缺少进程归属标识，Web 与新版具名 CLI 会拒绝向该 PID 发送停止信号。先在系统进程列表核实 Bot 的入口与 PID，再手动停止旧进程，之后从新版启动；不要直接依据过期 PID 文件结束进程。

完成「选择能力 → 创建凭证 → 启动 API」后，在「反代接入」选择部署方式。上游不需要填写：同机反代自动使用 http://127.0.0.1:8080；不同电脑选择 SSH 隧道，自动使用服务器的 http://127.0.0.1:18080。18080 是服务器的 loopback；固定端口被占用时先处理冲突。旧自定义上游保存新部署方式前保留，保存时会提示替换。

填写服务器 IPv4/域名、SSH 用户、端口（默认 22）、本机私钥绝对路径，保存后点击「连接隧道」。公钥需已加入服务器 authorized_keys；首次连接可在 Web 扫描指纹，独立核对后确认信任；冲突拒绝覆盖。可生成本机专用密钥，公钥手动授权或使用一次性服务器密码授权，要求服务器允许密码登录。页面不保存密码或私钥内容、不自动信任主机；后台使用系统 OpenSSH 并忽略个人 SSH 配置，要求非交互密钥认证，带口令的密钥需提前解锁并确保服务可访问密钥代理。服务器需允许 TCP 远程转发，不需要将 GatewayPorts 设置为公网监听。

隧道独立由 launchd/systemd 用户服务托管，退出 Web 不会断开；断线由系统重新启动（30 秒心跳、连续 3 次无响应退出）。API 与隧道分别自启，默认均关闭；Windows 使用当前用户交互登录的任务计划程序（需 OpenSSH，适配尚待 Windows 实机验收）；无用户服务管理器的平台暂不支持托管。修改连接配置或切换部署方式前先「断开并关闭自启」。电脑休眠或网络中断仍影响连接。

「刷新连接状态」区分进程运行与 SSH 控制连接；「验证服务器端口」通过 SSH 执行固定的 curl 健康检查，服务器需安装 curl，不会发送模型请求或调用凭证。「检查本机 API」固定检查本机 8080，「检查公网」检查 HTTPS 入口。最后部署生成的 Nginx 片段并用真实凭证调用。仅服务器内部使用时可直接请求自动上游，无需公网入口，仍需授权。SSH 模式可预览部署计划，确认后部署独立 Nginx/HTTPS 站点并通过 Certbot 申请和续期证书；需要 root、systemd、有效域名与 80/443，可选 apt/dnf 安装依赖。失败恢复原 Nginx 配置，已安装软件包和证书不自动删除。复杂网关/同机部署请由管理员使用配置片段处理。

先配置支持图片模型的 Provider，并通过 ai status 刷新目录。在「对外服务 → 能力开放」启用「图片生成」（images）和按需启用「图片编辑」（image_edits），再为服务器创建对应权限的独立凭证。旧凭证不会自动扩权。点击「启动服务」或执行 ai server start 即可后台运行，无需源码目录或 npm。托管服务固定监听 127.0.0.1:8080，只使用开放能力凭证；关闭管理页面和终端后继续运行。能力关闭和凭证撤销逐请求生效。

ai server start     # 后台启动
ai server status    # 状态与日志位置
ai server restart   # 重启；升级后刷新安装路径
ai server enable    # 开启自启并启动
ai server disable   # 关闭自启，保持运行
ai server stop      # 停止并关闭自启

Web「API 后台服务」提供相同操作。macOS 使用 launchd，开启自启后在用户登录时启动；Linux 使用 systemd 用户服务，无登录持续运行或开机启动需管理员配置 loginctl enable-linger USER。Windows 支持当前用户登录任务计划（需 OpenSSH，尚待实机验收）；无用户服务管理器的 Linux 和容器暂不支持托管。状态来自系统管理器，不代表真实模型调用成功；启动后刷新状态并检查日志。macOS 日志在配置目录的 api-service.log，Linux 使用状态返回的 journalctl --user -u ... 命令。多份配置不能占用同一端口，启动前停止原前台服务。开发调试仍可在源码目录执行 npm run server，用旧服务 Token 或能力凭证；AI_GATEWAY_SERVER_HOST / AI_GATEWAY_SERVER_PORT 仅对前台方式生效。日志轮转、复杂网关和系统权限仍需部署环境配置。

选择部署方式并填写 HTTPS 公网入口，上游自动生成，使用「接入测试」生成的 Nginx 片段部署 TLS。Runtime 在电脑上时先建立 VPN 或反向 SSH 隧道。管理页面 ai web 不对外开放；保存配置不会部署服务器，健康检查不代表模型调用成功。

curl https://ai.example.com/v1/images/generations \
  -H "Authorization: Bearer $AXIOM_SERVICE_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"model":"YOUR_IMAGE_MODEL","prompt":"画一只猫","n":1,"size":"1024x1024","response_format":"b64_json"}'

curl https://ai.example.com/v1/images/edits \
  -H "Authorization: Bearer $AXIOM_SERVICE_TOKEN" \
  -F 'model=YOUR_IMAGE_MODEL' -F 'prompt=将背景改为蓝色' \
  -F 'image=@reference.png'

生成接收 JSON，编辑接收 multipart；必须包含 model 和 prompt，n 为 1–8，size 为像素尺寸或 auto，response_format 为 url 或 b64_json，具体支持取决于 Provider。其余参数原样传递，不推断提示词中的张数或尺寸。编辑上传字段为 image 或重复的 image[]，1–8 张 PNG/JPEG/WebP，每张最多 20 MiB，含可选 mask 合计最多 40 MiB；不读取本机路径或下载请求中的图片 URL。

默认整个请求体最多 42 MiB（含 multipart 开销），调大 AI_GATEWAY_MAX_REQUEST_BYTES 时也须调整 Nginx 的 client_max_body_size。图片响应头等待至少 120 秒，可调高 AI_GATEWAY_UPSTREAM_HEADERS_TIMEOUT_MS。响应原样返回 data[].url 或 data[].b64_json，调用方下载或解码；Runtime 不托管图片，URL 有效期由 Provider 决定。请求只尝试首个健康模型候选一次，不自动重试或切换；超时、断网或 5xx 后先核实上游任务，避免重复计费。

无凭证 401、无能力 403、参数无效 400、体积超限 413、无可用模型 503、传输失败 502；响应已开始发送后若中断则关闭连接。凭证可设置 Provider/模型白名单、有效期、每分钟请求数和总请求额度，并可轮换 Token。额度为请求次数，失败请求也计数，重启/轮换/恢复不会重置；不是 Token 或金额预算。超限返回 429。

ai use claude

ai proxy
ai proxy 我的站 127.0.0.1 8081
ai proxy 我的站 --disable
ai proxy 127.0.0.1 8081
ai proxy 127.0.0.1:8081
ai proxy http://127.0.0.1:8081
ai proxy --disable
  • 无参数时先选择 Provider 或 Runtime 默认值，再输入主机/IP与端口；缺少协议时自动补为 http://。
  • 已有代理时先显示当前地址，再提供编辑、关闭和取消选项；不通过输入 off 关闭。
  • 新增或编辑（包括 ai provider edit 的 proxyUrl）先进行零 Token 的代理端点 TCP 连通检查；失败时保留原配置。
  • Provider 代理保存在 ~/.ai-gateway/providers.json，优先于 ~/.ai-gateway/runtime.json 的默认代理；清除 Provider 覆盖后回退默认值。
  • 模型探测和 Transport Proxy 上游按实际 Provider 选择代理；CLI 子进程使用启动 Provider 的代理环境。
  • 本地回环地址自动加入 NO_PROXY，避免 execution-scoped Transport Proxy 发生代理回环。
  • 不会修改 ~/.claude 或 ~/.codex；直接运行原生命令不受影响。

ai image 51talk-image "将图1人物融入图2场景" --image "./人物.png" --image "./场景.jpg"
  • 直接运行 ai image 时，会依次选择 Provider、具体模型和生成方式（文生图 / 参考本地图片）；参考图模式逐张输入文件路径，留空结束（达到 8 张自动结束），最后输入提示词。已有提示词的旧用法不增加交互。
  • 交互式只需在 Image prompt 描述明确数量和像素尺寸。支持“生成三张图片”、Generate three images 以及逐图尺寸列表，用逗号、顿号或分号分隔；未说明数量默认 1 张，未说明尺寸使用 Provider 默认。按明确句式解析，不调用额外模型，不保证理解任意自由表达。
  • --count 1..8 / --count=3 指定数量，--size WIDTHxHEIGHT / --size=auto 指定尺寸，可放在位置参数前后；与提示词明确数量/尺寸冲突时报错。宽高限制 64–8192 像素，总像素 ≤16,777,216，Provider 可有更小限制。
  • “多张/一套”但没有数量，或“多张不同尺寸”却没有像素尺寸，交互式按缺失字段追问数量或尺寸，保留原始提示词和参考图，已有提示词的命令行用法直接报错。场景内物体数量和引号内文字不作为输出数量，不从横竖版或宽高比猜尺寸。独立分句中的“2张图片”可被识别，“参考这几张图片”不算输出数量。数量追问直接回答 2 只补数量；尺寸追问按输出顺序填写 2160x3840,3840x2160，仅补尺寸。4K、手机或 PC 屏幕未给像素尺寸时会追问并提供示例，不自动猜测；纯数字不能替代图片描述。
  • 每张独立请求 n: 1 并传各自 size，顺序生成并共享整批 Transport Proxy；共同风格保留，但不保证跨图人物/版式完全一致。生成请求不原地重试；文生图自动切换受 ai failover on/off 控制。
  • 已知 DALL·E 尺寸限制在请求前校验，其他模型以上游实际响应为准，不静默换尺寸。base64 实际尺寸不符时保留文件、报告差异并标记任务失败；远程 URL 不下载，尺寸标记未验证。
  • 全部响应项在整批 8 张上限内保存或报告，文件名包含任务序号和请求尺寸；逐任务汇报结果，失败继续后续任务并保留已成功文件，任一任务失败退出码 1，不自动重跑整批。上游额外图片计入上限，余量耗尽不再请求。
  • 重复 --image <path> 或 --image=<path> 指定多张本地参考图，按输入顺序上传；最多 8 张，单张最大 20 MiB，合计最大 40 MiB。支持 PNG、JPEG、WebP，所有文件上传前按内容校验。路径有空格请加引号；不支持 GIF、URL 或 mask。原图不修改，结果另存新文件。
  • 参考图上传给所选 Provider，调用 multipart /v1/images/edits。Provider / 模型须支持相应的单图或多图编辑；模型列表存在不代表支持该接口。服务端仍可能拒绝格式、尺寸或能力。非兼容的 Responses 图片工具接口不在此功能范围。
  • 参考图不自动重试、不向其他 Provider fallback；所选 Provider 不健康时直接失败。只指定模型时按健康/顺序选择一个可用 Provider。仅使用可信服务商；失败后明确选其他服务商重新运行。文生图仅在开启自动降级时允许 fallback。
  • 第一个参数是 Provider 名；第二个参数匹配模型缓存时作为具体模型，否则从第二个参数开始作为提示词并使用默认模型。
  • 命令执行前会自动刷新模型缓存；也可以先运行 ai status 检查。指定模型时建议给提示词加引号。
  • b64_json 会以 0600 权限保存到当前目录并输出绝对路径；远程响应只接受无凭证的 https URL。
  • 图片请求等待响应头上限为 120 秒；参考图失败直接报告，文生图可尝试下一个 Provider。
  • 请求经过 execution-scoped Transport Proxy，真实 usage 复用唯一 UsageObserver 账本。

运行规则

  • 正整数 level 组成自动切换链；level: 0 只允许显式使用，不进入自动候选。
  • 用 ai failover off 可一键关闭自动降级：之后只尝试选定（或默认 level: 1）的 Provider，失败即报错不切换；ai failover on 恢复，ai failover 查看状态。关闭时同时停用连续响应头超时熔断，不因已有熔断或健康错误缓存跳过所选 Provider，每次 CLI 重试均实际访问上游；单次请求仍有 45 秒超时限制。开关在新启动的 execution 中生效，已有会话需退出后重启。
  • 显式指定 Provider 时不会先刷新全部 Provider，而是直接使用该 Provider 的已缓存模型并实际尝试；健康缓存暂时为 error 不会在请求前静默跳过，失败后才进入同模型族的自动切换链。
  • Claude Code 只在提供 Claude 模型的 Provider 间切换；Codex 只在提供 Codex/OpenAI 兼容模型的 Provider 间切换，不跨模型族。
  • 只有会产生补全的模型端点（/v1/messages、/v1/chat/completions、/v1/completions、/v1/responses、/v1/embeddings、/v1/images/generations、/v1/images/edits）的带请求体 POST 参与降级：在产生有效输出前遇到连接错误、认证错误、限流或上游故障时，会在同一 Claude Code/Codex 会话内切换 Provider、改写备用模型并显示提示。multipart 参考图上传是例外，不自动重试或轮转。
  • CLI 启动期的无请求体 GET 探测，以及辅助端点（多数中转站未实现的 /v1/messages/count_tokens 等）的 404，都会原样返回给 CLI，既不触发 Provider 轮转，也不计入健康分。
  • 一次失败不会立刻换 Provider：限流（429）、5xx、连接层错误和有效输出前的流中断先在当前 Provider 原地重试（默认最多 2 次尝试，退避 300ms 起翻倍），重试额度用尽才轮转；401/403/404 与响应头超时是确定性失败，不重试直接换下一跳。重试成功不计失败、不扣健康分，重试全部失败整段只记一次失败。
  • 已经产生文字、推理或工具参数后不会静默重放；用户在当前 CLI 中重新提交或使用原生重试动作即确认切换，下一次请求使用备用 Provider。
  • 真实成功的健康检查把该 Provider 的健康分直接恢复到满分，历史误判扣分不会长期滞留。
  • Claude Code 使用临时 --settings 注入环境变量，不修改用户 settings；本次子进程会移除继承的 ANTHROPIC_AUTH_TOKEN，临时 settings 还会用空值遮蔽用户 settings 里的同名变量，避免与所选 Provider 的 ANTHROPIC_API_KEY 形成双认证。
  • ai use codex 使用本次子进程的 -c model_provider=... 固定所选 provider，并通过 env_key = "OPENAI_API_KEY" 使用 AI Gateway 注入的 Key；不会修改 Codex 全局认证或配置。
  • provider 的 mode 为 auto 时，非 root 执行 Claude Code 会追加 --dangerously-skip-permissions；ask 模式不会追加，并会在启动前确认。root 下请求 auto 会被安全约束为默认权限，临时 settings 中继承的 bypass 配置也会被清除。
  • OpenAI 兼容地址用于 Codex 时会使用 /v1，用于 Claude 时会去掉 /v1。
  • Claude 与 Codex 的本次子进程都会通过 execution-scoped 本地代理转发；原生终端交互不变，provider 返回的真实 usage 会按 provider/model 写入 usage.json。
  • 日志只记录 Key 指纹，不记录完整 API Key。

models 只对选中的 provider 调用 GET /models，刷新并列出完整模型目录，不调用推理端点、不产生推理 Token，也不覆盖已有真实健康状态。若 provider 不开放模型目录，models 会如实报告 404、451 等目录错误；这不代表缓存模型不可用，可改用 check 做最小真实验证。check 复用与 status 相同的真实验证规则，但只刷新一个 provider；省略名称时交互选择，提供名称时精确匹配，不会检查其他 provider。status 会刷新全部 provider 模型缓存，并从实际存在的 Claude/Codex 模型族中各选一个代表模型做真实调用验证；Codex 优先使用 Responses API。已通过手工模型验证但不开放模型目录的 provider 会使用缓存模型继续真实检查，不会因为 GET /models 返回 451 而直接判错。每次验证使用最短输入且输出上限为 1 token，不逐个验证全部模型，也不自动重试产生 Token 的请求。代表模型最多等待 30 秒；本地超时时上游仍可能已经处理成功，因此显示 unknown。验证返回的结构化 usage 会计入统一账本。
