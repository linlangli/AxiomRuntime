使用 Claude Code 或 Codex

默认 provider 和默认模型

ai use claude
ai use codex

指定 provider

ai use claude 51talk
ai use codex 51talk

指定 provider 和模型

ai use claude 51talk claude-opus-4-6
ai use codex 51talk gpt-5.5

自动降级

  • 不指定 provider 时，使用 level: 1。
  • 不指定模型时，使用 provider 默认 model。
  • provider 不可用时，按 level 自动降级。
  • 启动 Claude Code 时会使用临时 --settings 文件注入 ANTHROPIC_API_KEY 和 ANTHROPIC_BASE_URL，不会修改用户 settings，也不会使用 --bare。
  • 如果 provider 地址是 https://icode.51talk.biz/v1，Claude Code 会自动注入根地址 https://icode.51talk.biz；Codex 仍使用 /v1。
  • 启动记录会写入日志，包含 provider、baseUrl、模型、启动参数和 Key 指纹，不包含完整 Key。

ai hermes
ai hermes add
ai hermes list
ai hermes edit
ai hermes status
ai hermes use robot-name
ai use hermes robot-name

维护和迁移

ai hermes clear
ai hermes delete
ai hermes export robot-name
ai hermes import-local
ai hermes import ./hermes-robot.json
  • add 通过交互选择 AI Gateway provider、模型、mode，并可选择是否绑定 Telegram。
  • edit 可修改机器人名称、默认 provider、默认 model、mode 和 Telegram 绑定。
  • Telegram 不是必填项；Hermes cron job 只作为该机器人下面的 task。
  • task 的定时规则不写入 hermes.json，需要通过和机器人聊天或后续 task 管理功能修改。
  • list 只列出机器人配置，不刷新健康度。
  • status 检查 Hermes CLI、provider、模型缓存和 Telegram 绑定状态。
  • use 使用 ~/.ai-gateway/hermes/<机器人名称>/ 独立运行目录启动 Hermes，不读取全局 ~/.hermes/config.yaml 的 API Key。
  • clear 清空机器人状态和记忆，保留配置。
  • delete 删除机器人配置和 AI Gateway 管理状态。
  • export 不导出 API Key，可复制到其他电脑后用 import 导入。
  • import-local 自动扫描本机 ~/.hermes，导入默认 Hermes 机器人和该机器人下面的 tasks。

状态和检查

ai provider list
ai status
ai log
ai context
ai session
ai session list
ai session clear
ai report
ai doctor
ai doctor --deep
  • provider list 只读取配置，以卡片形式展示 provider 的名称、地址、Key、level、mode 和默认模型。
  • status 会轻量刷新所有 provider，不发送真实对话请求，默认不消耗 token。
  • status 展示健康度、Claude/Codex 各自的有效 baseUrl、兼容模型、真实 token 使用量和使用占比。
  • log 打开日志文件；log --print 以分块形式在终端输出最近日志。
  • context 生成并打开 .ai-gateway/context.md，用于给 Claude/Codex 提供项目上下文。
  • session 进入最近 session 选择列表；session list 列出最近 session；session clear 清空 AI Gateway session 记录。
  • report 选择 session 生成 Markdown 报告，包含 context、真实 token、模型、provider 快照和画像信息。
  • doctor 检查配置文件、CLI、连通性、模型探测、level 冲突和默认模型。
  • doctor --deep 使用最高优先级可用 provider 验证真实推理链路，支持自动降级，可能消耗 token。
  • 如果 provider 返回 usage，doctor --deep 会写入真实 token 使用记录。
  • 如果没有 provider 可用，doctor --deep 会自动回到普通 doctor，不使用大模型。

继续上次会话

ai last

继续使用上次选择的工具、provider 和模型。

Web 控制面板

ai web

规划中的命令。当前基础版会提示暂未实现，后续用于查看 provider、健康度、使用占比、消耗曲线和可视化配置。

配置文件

用户可编辑：~/.ai-gateway/providers.json

[
  {
    "name": "51talk",
    "baseUrl": "https://example.com",
    "apiKey": "sk-xxx",
    "mode": "auto",
    "level": 1,
    "model": "claude-opus-4-6"
  }
]
