通过 npm 安装

node --version
npm install --global @offerpilot/axiomruntime
ai --version
ai setup

npm 包名是 @offerpilot/axiomruntime，安装后注册的可执行命令是 ai。需要 Node.js 22.19.0+。

如果 npm 显示 EBADENGINE，请先升级 Node.js 再重新安装，不要继续使用警告状态下安装的 CLI。

ai --version 无副作用地验证安装；ai setup 初始化 Runtime，并可在确认后安装缺失的 Claude Code/Codex。

全局安装可以由 root 完成，但日常执行和常驻服务应使用专用非 root 用户。root 下请求 Claude auto/bypassPermissions 时，Runtime 会安全约束为默认权限并告警，不会传递 --dangerously-skip-permissions。

brew tap linlangli/axiom https://gitlab.com/linlangli/axiom.git
brew install linlangli/axiom/axiomruntime
ai --version
ai setup

Homebrew Formula 复用同版本 npm tarball并校验 SHA256，固定使用 Homebrew node@22。非 GitHub Tap 首次添加时需提供公开 Git URL。

使用模型

启动 Claude Code 或 Codex

ai use claude
ai use codex
ai use claude 51talk
ai use codex 51talk gpt-5.5

不指定 provider 时使用 level: 1；不指定模型时使用 provider 默认 model。

生成图片

ai image
ai image 51talk-image "一只戴墨镜的猫，数字插画"
ai image 51talk-image gpt-image-2 "一只戴墨镜的猫，数字插画"
  • 直接运行 ai image 时，会依次选择 Provider、具体模型并输入提示词。
  • 第一个参数是 Provider 名；第二个参数匹配模型缓存时作为具体模型，否则从第二个参数开始作为提示词并使用默认模型。
  • 命令执行前会自动刷新模型缓存；也可以先运行 ai status 检查。指定模型时建议给提示词加引号。
  • b64_json 会以 0600 权限保存到当前目录并输出绝对路径；远程响应只接受无凭证的 https URL。
  • 图片请求最长等待 120 秒；超时会自动失败并尝试下一个 Provider。
  • 请求经过 execution-scoped Transport Proxy，真实 usage 复用唯一 UsageObserver 账本。

运行规则

  • provider 不可用时按 level 自动降级。
  • Claude Code 使用临时 --settings 注入环境变量，不修改用户 settings。
  • ai use codex 使用本次子进程的 -c model_provider=... 固定所选 provider，并通过 env_key = "OPENAI_API_KEY" 使用 AI Gateway 注入的 Key；不会修改 Codex 全局认证或配置。
  • provider 的 mode 为 auto 时，非 root 执行 Claude Code 会追加 --dangerously-skip-permissions；ask 模式不会追加，并会在启动前确认。root 下请求 auto 会被安全约束为默认权限，临时 settings 中继承的 bypass 配置也会被清除。
  • OpenAI 兼容地址用于 Codex 时会使用 /v1，用于 Claude 时会去掉 /v1。
  • Claude 与 Codex 的本次子进程都会通过 execution-scoped 本地代理转发；原生终端交互不变，provider 返回的真实 usage 会按 provider/model 写入 usage.json。
  • 日志只记录 Key 指纹，不记录完整 API Key。
持久设置 Codex App provider 
ai set codex chatgpt
ai set codex provider 51talk-cq gpt-5.6-sol
ai set codex provider 51talk-cq
ai set codex provider
ai set codex proxy 127.0.0.1:7890
ai set codex proxy off
  • chatgpt 调用 codex login 打开浏览器，并在成功后选择内建 model_provider = "openai"。
  • provider name model-id 显式选择该 provider 已探测的 gpt-* 模型；只给 provider 时自动选最新 GPT。
  • provider 不带名称时依次交互选择已添加的 provider 和 GPT 模型；没有可用 GPT 时提示运行 ai status，不修改配置。
  • 自动选择先比较 GPT 数字版本，同版本优先 sol、pro、alias、codex、terra、mini、luna、nano，并优先滚动 alias。API Key 只写入 mode 0600 的 auth.json。
  • 写入 config.toml 前会规范化 base_url：末尾没有 /v1 时自动补上，已有时不重复追加。
  • 原有 project、MCP、plugin、feature 设置会保留；任一步失败会恢复原 config.toml 和 auth.json。
  • 切换自定义 provider 会替换当前 ChatGPT token；切回 ChatGPT 时需重新登录。
  • 成功后 macOS 会重启 Codex.app 或当前名称的 ChatGPT.app，并清理重启进程继承的 OPENAI_API_KEY，确保客户端读取刚写入的 auth.json；无法自动重启时按提示手动操作。
  • proxy 把裸 host:port 规范化为 HTTP origin，只更新 shell_environment_policy.set 的大小写 HTTP(S)/ALL proxy keys；off 清除这些 managed keys，不修改 auth.json。
  • Proxy URL 禁止包含账号密码、path、query 或 fragment，command usage log 会整体脱敏。macOS 会同步当前登录会话的 user launchd environment；失败时恢复原 config 且不重启，注销或重启 macOS 后需重新运行本命令。

Memory 配置

向量检索模型 
ai memory embedding
ai memory embedding set
ai memory embedding set jina https://api.jina.ai/v1 jina_xxx jina-embeddings-v3 --type jina
ai memory embedding test "ping"
ai memory embedding clear
  • ai memory embedding 会进入交互菜单，可查看、设置、测试或清空 embedding 配置。
  • 这组配置只服务记忆检索，不参与 Claude Code / Codex 聊天 provider 选择。
  • Jina 会默认写入 retrieval.query 和 retrieval.passage，后续向量查询和记忆入库可分别使用。
  • set 后会调用 embeddings 接口做一次轻量验证；需要跳过时可加 --skip-test。
  • API Key 只保存在本机 ~/.ai-gateway/memory.json，日志会脱敏。

Provider 管理

添加、编辑、删除 
ai provider add
ai provider add 51talk https://example.com sk-xxx
ai provider edit
ai provider edit 51talk
ai provider delete
ai provider delete 51talk
ai provider list
  • mode 可选 ask 或 auto。
  • level 是优先级；如果目标等级已占用，会和对应 provider 交换。
  • model 从已探测模型中选择，不手动输入。
  • 删除 provider 会清理模型缓存；后续执行会按 level 从剩余 provider 中重新选择。

Telegram Bot

配置和进程管理 
ai telegram                 # 交互选择操作，再选择目标 Bot
ai telegram --bot ops       # 预选 ops，再进入交互菜单
ai telegram add ops
ai telegram add support
ai telegram list

ai telegram config show --bot ops
ai telegram config set token <bot-token> --bot ops
ai telegram config set allowedUserIds 123456789,987654321 --bot ops
ai telegram config set defaultEngine codex --bot ops
ai telegram config set defaultCwd /workspace/ops --bot ops
ai telegram edit --bot ops

ai telegram start --bot ops
ai telegram stop --bot ops
ai telegram status --bot ops
ai telegram logs --bot ops -f
ai telegram doctor --bot ops
ai telegram delete --bot ops

ai telegram start --all
ai telegram stop --all
ai telegram status --all
  • --bot=<name> 与 --bot <name> 等价。旧位置参数写法继续兼容；新脚本推荐显式指定 --bot 或 --all。
  • 裸 ai telegram 会先选操作再列出 Bot；生命周期菜单可选 all bots，删除菜单会二次确认。带 --bot 进入交互菜单时会跳过 Bot 选择。
  • edit 交互式编辑指定 Bot；delete 先停止目标 Bot，再删除该 Bot 的 config、PID、log 和 SQLite 文件。旧 remove 是兼容别名。
  • legacy telegram.json 首次会自动迁移为命名 Bot default；删除 default 后，列表、生命周期命令和 Bot 服务不会再从 legacy 配置重建它。无目标 ai telegram config 仍可管理 legacy global config。
  • config set ... --bot <name> 只修改指定 Bot，不影响全局或其他 Bot；token 不会出现在命令日志或终端输出中。
  • 命名 Bot 的配置、PID、日志和会话保存在 ~/.ai-gateway/telegram/bots/<name>.json|.pid|.log|.sqlite。
  • 为保持兼容，存在命名 Bot 时，无目标 start、stop、status 仍作用于全部命名 Bot。
  • 默认只有 allowedUserIds 中的 Telegram 用户可以访问 Bot；如需开放给所有用户，显式设置 allowAllUsers: true。
  • 远程执行复用 AI Gateway 顶层 provider；不配置固定 provider/model 时按优先级自动选择。
  • /start 或 /reset 先选择 Provider/Model，再直接以按钮列出历史绝对路径，末尾可选择“自定义”，不再先点击“已存在”。
  • /provider 以按钮列出全部 AI Provider，可编辑名称、Base URL、API Key、默认模型、模式和优先级，二次确认后删除，或从列表底部添加。操作复用 ai provider 的核心 CRUD 和检查逻辑。
  • Provider API Key 在详情中只显示“已配置”，不会写入 Bot 应用日志；输入后 Bot 会尽力立即删除该 Telegram 消息。未完成表单在 Bot 重启后需要重新开始。
  • Telegram Codex 执行会自动走本地 OpenAI 兼容代理记录 provider usage；/usage 有 provider cost 时直接展示，否则按 model-pricing.json 估算。
  • 如果本机不能直连 api.telegram.org，设置 proxyUrl 或环境变量 HTTPS_PROXY / ALL_PROXY。交互式新增或编辑 Bot 时，proxyUrl 输入提示会展示完整 URL 示例；地址请包含协议，例如 http://127.0.0.1:7890。
Bot 命令 
/claude prompt
/codex prompt
/reset
/fresh
/cwd /path/to/project
/config
/provider
/usage
/pin
/unpin
/terminal ls -la
/restart
/help
  • 普通文本会发送给当前会话的默认引擎。
  • 基础菜单同时提供 Memory、上下文固定、终端和重启命令；选择 CLI 后，会在当前 chat 的 / 菜单追加该 CLI 的 slash 命令映射。
  • CLI slash 命令不会以消息列表形式额外刷屏，点击菜单项后会转发给当前 CLI 执行。
  • 会话按 1400 token budget 动态选择最近上下文；回复 Bot 回答并发送 /pin 可固定最多 3 个关键 turn，/unpin 可撤销。
  • 回复文字或 caption 会注入转义后的引用上下文；编辑最新普通 prompt 会停止旧任务、清除旧 native session 后重跑。
  • 下一条请求最多消费 8 个附件：UTF-8 文本单文件 ≤2MB、图片单文件 ≤10MB；Codex 图片使用 --image。
  • 进度消息按至少 1500ms 节流显示阶段、工具和有界回答预览；最终结果替换同一条消息。
  • /terminal 最长运行 60 秒且高风险命令必须确认；/restart 会优雅停止并启动 replacement process。
  • Claude 失败会显示 terminal error，不再把 system/init JSON 当作主错误。
  • full-auto 会映射到 Claude/Codex 的跳过审批模式，但高风险命令文本仍会在 Telegram 侧强制确认。

状态和诊断

轻量检查

ai status
ai provider list
ai log
ai log --print
ai context

status 会刷新 provider 模型缓存，并从实际存在的 Claude/Codex 模型族中各选一个代表模型做真实调用验证；每次使用最短输入且输出上限为 1 token，不逐个验证全部模型，也不自动重试产生 Token 的请求。结果分别展示模型发现、Claude、Codex 的真实状态、验证模型和失败原因。验证返回的结构化 usage 会计入统一账本；周统计按 provider 精确名称聚合，同一 provider 的不同模型合并，事件仍保留 model 明细。

诊断与自动修复

ai doctor
ai doctor --local
ai doctor --no-fix
ai doctor --strict
ai doctor --deep --tool codex
ai doctor --deep --tool claude

默认创建缺失的 Runtime 状态文件，并备份后重建损坏的可再生文件；不会读取或修改项目源码，也不会自动覆盖 providers.json。--deep 可能消耗 token。

会话和报告

Session

ai session
ai session list
ai session clear

session 进入最近 session 选择列表；session clear 清空 AI Gateway 记录。

Report

ai report

选择 session 生成 Markdown 报告，包含 context、真实 token、模型、provider 快照和画像信息。

配置文件

用户可编辑 
~/.ai-gateway/providers.json

providers.json 保存聊天 provider；memory.json 保存记忆检索 embedding 模型。model-pricing.json 保存美元 / 百万 token 的模型价格。

注意：这两个文件当前都以明文保存 apiKey。请限制文件权限并且不要提交到仓库。凭证改由 SecretStore 管理、配置只留 apiKeyRef 是目标架构，尚未实现。
