通过 npm 安装

node --version
npm install --global @offerpilot/axiomruntime
ai --version
ai setup

npm 包名是 @offerpilot/axiomruntime，安装后注册的可执行命令是 ai。需要 Node.js 22.19.0+。

如果 npm 显示 EBADENGINE，请先升级 Node.js 再重新安装，不要继续使用警告状态下安装的 CLI。

ai --version 无副作用地验证安装；ai setup 初始化 Runtime，并可在确认后安装缺失的 Claude Code/Codex。源码安装在仓库根目录依次执行 npm ci、npm ci --prefix web、npm run link，先构建 CLI/控制面再全局链接。npm run smoke:package 在临时目录安装真实 npm 包并验证 CLI、鉴权 API、历史备份/回滚、HTML/JS/CSS；不修改全局链接或用户真实配置。CI 包含 Linux/macOS/Windows matrix，正式 npm 发布也需通过。

全局安装可以由 root 完成，但日常执行和常驻服务应使用专用非 root 用户。root 下请求 Claude auto/bypassPermissions 时，Runtime 会安全约束为默认权限并告警，不会传递 --dangerously-skip-permissions。

brew tap linlangli/axiom https://github.com/linlangli/AxiomRuntime.git
brew install linlangli/axiom/axiomruntime
ai --version
ai setup

Homebrew Formula 复用同版本 npm tarball并校验 SHA256，固定使用 Homebrew node@22。Tap 名保留 linlangli/axiom，首次添加时必须提供实际的 GitHub URL。已有旧 GitLab Tap 的用户先更新 remote：

git -C "$(brew --repo linlangli/axiom)" remote set-url origin https://github.com/linlangli/AxiomRuntime.git
brew update

维护者发布与 CI 配置

源码仓库为 linlangli/AxiomRuntime。原 .gitlab-ci.yml 保留；GitHub 托管 runner 负责测试、门户构建与 SSH 部署，无需在生产服务器安装 Actions runner。branch push 和 PR 执行完整测试及前端类型检查，默认分支测试成功后部署门户；v* tag 单独触发 npm 发布。

在 Settings → Environments 中配置 portal-production，仅允许 main branch。Variables 包含必填的 PORTAL_SSH_HOST；可选的 PORTAL_SSH_USER、PORTAL_DEPLOY_ROOT、PORTAL_HEALTH_URL 分别默认 axiom-portal-deploy、/srv/axiomruntime-portal、https://axiom.offerpilot.life/。Secrets 包含 PORTAL_SSH_PRIVATE_KEY_B64 和已核对主机公钥的 PORTAL_SSH_KNOWN_HOSTS。部署按顺序执行，健康检查失败恢复上一 release。

npm-production 仅允许 v* tag，无需 npm Secret。在 npm 包 @offerpilot/axiomruntime 的 Settings → Trusted Publisher 创建 GitHub Actions connection：owner linlangli、repository AxiomRuntime、workflow filename publish.yml、environment npm-production，仅启用 Allow npm publish。GitHub 通过 OIDC 获取短期凭证并生成 provenance；workflow 使用 npm@11.11.0，只有 npm job 有 id-token: write。GitLab variables 不随 Git 迁移，门户 SSH 凭证需重新注入；原 GitLab CI 继续使用原有 NPM_TOKEN。

双击 发布.command 或执行 npm run release 打开发布助手。助手使用 gh 检查登录及发布 workflow，在临时目录合并远端 main，安装根目录与前端依赖并运行完整测试，确认后推送 release commit 与 tag，等待 Publish npm 结果。npm 信任连接必须提前配置，助手不能通过 GitHub API 读取 npm 端状态。如果 npm 显示 Pending validation，须在页面给定截止时间前完成一次获准的新版本发布；仅保存连接不代表发布认证已经验证。tag 提交必须属于默认分支，版本必须与 package.json.version 一致。Homebrew 单独同步 npm latest 的 tarball 与 SHA256。Git 历史迁移应先备份本机 refs；未提交修改、GitLab Issues、CI variables 和 artifacts 不包含在 Git push 中。

向服务器开放图片 API

新模型请求在「运行记录 → 调用记录」显示独立 traceId、父 executionId、已观测 Token、成本及来源和终止耗时；旧记录缺少关联时显示未知，辅助请求不进入模型调用汇总。工具会话区分启动配置与最近成功的实际 Provider/模型，信号退出按失败记录。历史存储、备份与回滚的完整命令见「凭据与历史」分类。

按引导连接服务器

「验证与调用 → 实际调用工作台」支持对话、Responses、向量、图片生成/参考图上传编辑、隔离工作区 Agent，以及 tools 注册工具执行。工作台始终保留，凭证仅用于本次本机或公网请求，不保存；真实调用会产生费用，响应限 40 MiB。公网授权调用成功且响应符合协议才标记部署验证通过；配置变化后验证失效。当前工具只提供 runtime.status 与 providers.list，请求 POST /v1/tools/execute，请求体为 {"name":"runtime.status"}，不执行任意 Shell 命令。

「本地配置 → 工具配置」可备份并持久保存 Claude 用户连接，保留其他字段；「消息接入」支持 Bot 启动、停止、重启、删除配置（保留数据库与日志）。「运行记录」与「用量统计」提供完整历史分页、CSV/JSON 下载及每 2 秒实时刷新，内容为安全字段投影；SQLite 用量/会话可索引分页，日志页仅保留当前页；完整调用聚合仍需扫描，长期容量尚待验收。SSH 连接参数进入快照，但专用私钥、主机信任、请求计数、部署验证证据不进入快照；恢复 SSH 配置前需断开隧道并关闭自启。

「对外服务」使用唯一四步导航：「开放能力 → 调用凭证 → 启动与连接 → 验证与调用」。侧栏显示各步已保存状态与摘要，可自由返回；首次进入根据保存的能力、有效凭证和 API/隧道状态定位首个未完成步骤，状态刷新不会切走当前步骤，切步保留草稿。技术参数、指纹与密钥准备及「运行管理与连接详情」按需展开；窄屏使用横向紧凑四步导航，表单纵向排列。

旧版启动的 Bot 若缺少进程归属标识，Web 与新版具名 CLI 会拒绝向该 PID 发送停止信号。先在系统进程列表核实 Bot 的入口与 PID，再手动停止旧进程，之后从新版启动；不要直接依据过期 PID 文件结束进程。

  1. 开放能力：选择需要的接口，预览变更并确认保存后继续。
  2. 调用凭证：创建最小权限凭证，复制仅显示一次的 Token，确认已经保存后继续；已有有效凭证可直接继续。有效凭证须未过期，且与已保存能力至少有一项交集，旧凭证不会自动扩权。
  3. 启动与连接：选择同机或本机通过 SSH 连接服务器。SSH 信息填好后点击「启动 API 并连接服务器」，依次保存接入配置与 SSH 配置、启动 API、连接隧道；接入配置变更需先预览确认，已完成操作会跳过，失败停止后续操作并保留成功状态。同机模式跳过 SSH。此操作不会开启自启或部署远端 Nginx；「仅保存 SSH 配置」无需 API 运行，也不会连接。
  4. 验证与调用：选择服务器内部调用或公网 HTTPS。内部调用无需域名，直接使用自动上游；公网模式保存入口后可预览远端部署或使用 Nginx 片段。展开健康检查与调用示例，最后用真实凭证完成授权调用。

上游不需要填写：同机自动使用 http://127.0.0.1:8080；SSH 模式使用服务器的 http://127.0.0.1:18080。18080 是服务器的 loopback；固定端口被占用时先处理冲突。旧自定义上游保存新部署方式前保留，保存时会提示替换。保存与步骤切换不会启动 API、连接 SSH 或修改远端服务器。

SSH 需要服务器 IPv4/域名、SSH 用户、端口（默认 22）、本机私钥绝对路径。公钥需已加入服务器 authorized_keys；首次连接可展开准备区扫描指纹，独立核对后确认信任；冲突拒绝覆盖。可在未填写服务器时生成或复用本机专用密钥，不覆盖已有私钥。扫描指纹需要服务器地址、SSH 用户与有效端口；诊断还需私钥路径。缺少信息或操作锁定时，按钮下方显示原因。隧道运行或开启自启时仍可扫描和诊断；修改密钥、信任与公钥授权需先断开并关闭自启。公钥可手动授权或使用一次性服务器密码授权，要求服务器允许密码登录。页面不保存密码或私钥内容、不自动信任主机；后台使用系统 OpenSSH 并忽略个人 SSH 配置，要求非交互密钥认证，带口令的密钥需提前解锁并确保服务可访问密钥代理。服务器需允许 TCP 远程转发，不需要将 GatewayPorts 设置为公网监听。

隧道独立由 launchd/systemd 用户服务托管，退出 Web 不会断开；断线由系统重新启动（30 秒心跳、连续 3 次无响应退出）。API 与隧道分别自启，默认均关闭；Windows 使用当前用户交互登录的任务计划程序（需 OpenSSH，适配尚待 Windows 实机验收）；无用户服务管理器的平台暂不支持托管。修改连接配置或切换部署方式前先「断开隧道并关闭自启」。电脑休眠或网络中断仍影响连接。

「刷新服务与连接状态」和「刷新运行状态」区分进程运行与 SSH 控制连接；「验证服务器端口」通过 SSH 执行固定的 curl 健康检查，服务器需安装 curl，不会发送模型请求或调用凭证。「验证与调用」的本机 API 检查固定访问本机 8080，公网检查访问保存的 HTTPS 入口。仅服务器内部使用时无需公网入口，仍需授权。公网模式下，SSH 可预览部署计划，确认后部署独立 Nginx/HTTPS 站点并通过 Certbot 申请和续期证书；需要 root、systemd、有效域名与 80/443，可选 apt/dnf 安装依赖。失败恢复原 Nginx 配置，已安装软件包和证书不自动删除。复杂网关/同机部署请由管理员使用配置片段处理。进程运行、隧道连通与健康检查不能代替真实授权调用。

先配置支持图片模型的 Provider，并通过 ai status 刷新目录。在「对外服务 → 开放能力」启用「图片生成」（images）和按需启用「图片编辑」（image_edits），再为服务器创建对应权限的独立凭证。在「启动与连接」启动 API 或执行 ai server start 即可后台运行，无需源码目录或 npm。托管服务固定监听 127.0.0.1:8080，只使用开放能力凭证；关闭管理页面和终端后继续运行。能力关闭和凭证撤销逐请求生效。

ai server start     # 后台启动
ai server status    # 状态与日志位置
ai server restart   # 重启；升级后刷新安装路径
ai server enable    # 开启自启并启动
ai server disable   # 关闭自启，保持运行
ai server stop      # 停止并关闭自启

Web「启动与连接 → 运行管理与连接详情」提供相同操作。macOS 使用 launchd，开启自启后在用户登录时启动；Linux 使用 systemd 用户服务，无登录持续运行或开机启动需管理员配置 loginctl enable-linger USER。Windows 支持当前用户登录任务计划（需 OpenSSH，尚待实机验收）；无用户服务管理器的 Linux 和容器暂不支持托管。状态来自系统管理器，不代表真实模型调用成功；启动后刷新状态并检查日志。macOS 日志在配置目录的 api-service.log，Linux 使用状态返回的 journalctl --user -u ... 命令。多份配置不能占用同一端口，启动前停止原前台服务。开发调试仍可在源码目录执行 npm run server，用旧服务 Token 或能力凭证；AI_GATEWAY_SERVER_HOST / AI_GATEWAY_SERVER_PORT 仅对前台方式生效。日志轮转、复杂网关和系统权限仍需部署环境配置。

公网使用时，在「验证与调用」保存 HTTPS 入口，再显式部署 Nginx/TLS；仅服务器内部使用时直接请求自动上游，无需域名。Runtime 在电脑上时，可在「启动与连接」建立反向 SSH 隧道。管理页面 ai web 不对外开放。

curl https://ai.example.com/v1/images/generations \
  -H "Authorization: Bearer $AXIOM_SERVICE_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"model":"YOUR_IMAGE_MODEL","prompt":"画一只猫","n":1,"size":"1024x1024","response_format":"b64_json"}'

curl https://ai.example.com/v1/images/edits \
  -H "Authorization: Bearer $AXIOM_SERVICE_TOKEN" \
  -F 'model=YOUR_IMAGE_MODEL' -F 'prompt=将背景改为蓝色' \
  -F 'image=@reference.png'

生成接收 JSON，编辑接收 multipart；必须包含 model 和 prompt，n 为 1–8，size 为像素尺寸或 auto，response_format 为 url 或 b64_json，具体支持取决于 Provider。其余参数原样传递，不推断提示词中的张数或尺寸。编辑上传字段为 image 或重复的 image[]，1–8 张 PNG/JPEG/WebP，每张最多 20 MiB，含可选 mask 合计最多 40 MiB；不读取本机路径或下载请求中的图片 URL。

默认整个请求体最多 42 MiB（含 multipart 开销），调大 AI_GATEWAY_MAX_REQUEST_BYTES 时也须调整 Nginx 的 client_max_body_size。Runtime server 的图片响应头等待由 AI_GATEWAY_UPSTREAM_HEADERS_TIMEOUT_MS 控制。响应原样返回 data[].url 或 data[].b64_json，调用方下载或解码；Runtime 不托管图片，URL 有效期由 Provider 决定。请求只尝试首个健康模型候选一次，不自动重试或切换；超时、断网或 5xx 后先核实上游任务，避免重复计费。

无凭证 401、无能力 403、参数无效 400、体积超限 413、无可用模型 503、传输失败 502；响应已开始发送后若中断则关闭连接。凭证可设置 Provider/模型白名单、有效期、每分钟请求数和总请求额度，并可轮换 Token。额度为请求次数，失败请求也计数，重启/轮换/恢复不会重置；不是 Token 或金额预算。超限返回 429。

ai image
ai image 51talk-image "一只戴墨镜的猫，数字插画"
ai image 51talk-image "生成3张咖啡店宣传图：一张1024x1024方图、一张1536x1024横图、一张1024x1536竖图，保持统一风格"
ai image 51talk-image "咖啡店宣传海报" --count 3 --size 1024x1024
ai image 51talk-image gpt-image-2 "一只戴墨镜的猫，数字插画"
ai image 51talk-image "保持人物一致，改成水彩风格" --image "./参考图.png"
ai image 51talk-image "将图1人物融入图2场景" --image "./人物.png" --image "./场景.jpg"
ai image recover "./.ai-image-recovery/响应记录.json"
  • 直接运行 ai image 时，会依次选择 Provider、具体模型和生成方式（文生图 / 参考本地图片）；参考图模式逐张输入文件路径，留空结束（达到 8 张自动结束），最后输入提示词。已有提示词的旧用法不增加交互。
  • 交互式只需在 Image prompt 描述明确数量和像素尺寸。支持“生成三张图片”、Generate three images 以及逐图尺寸列表，用逗号、顿号或分号分隔；未说明数量默认 1 张，未说明尺寸使用 Provider 默认。按明确句式解析，不调用额外模型，不保证理解任意自由表达。
  • --count 1..8 / --count=3 指定数量，--size WIDTHxHEIGHT / --size=auto 指定尺寸，可放在位置参数前后；与提示词明确数量/尺寸冲突时报错。宽高限制 64–8192 像素，总像素 ≤16,777,216，Provider 可有更小限制。
  • “多张/一套”但没有数量，或“多张不同尺寸”却没有像素尺寸，交互式按缺失字段追问数量或尺寸，保留原始提示词和参考图，已有提示词的命令行用法直接报错。场景内物体数量和引号内文字不作为输出数量，不从横竖版或宽高比猜尺寸。独立分句中的“2张图片”可被识别，“参考这几张图片”不算输出数量。数量追问直接回答 2 只补数量；尺寸追问按输出顺序填写 2160x3840,3840x2160，仅补尺寸。4K、手机或 PC 屏幕未给像素尺寸时会追问并提供示例，不自动猜测；纯数字不能替代图片描述。
  • 每张独立请求 n: 1 并传各自 size，顺序生成并共享整批 Transport Proxy；共同风格保留，但不保证跨图人物/版式完全一致。文生图和参考图均只向一个 Provider 尝试一次，不因超时、断网、HTTP 错误或保存失败自动重试或切换，避免重复计费。
  • 已知 DALL·E 尺寸限制在请求前校验，其他模型以上游实际响应为准，不静默换尺寸。base64 实际尺寸不符时保留文件、报告差异并标记任务失败；远程 URL 不下载，尺寸标记未验证。
  • 全部响应项在整批 8 张上限内保存或报告，文件名包含任务序号和请求尺寸；逐任务汇报结果，失败继续后续任务并保留已成功文件，任一任务失败退出码 1，不自动重跑整批。上游额外图片计入上限，余量耗尽不再请求。
  • 重复 --image <path> 或 --image=<path> 指定多张本地参考图，按输入顺序上传；最多 8 张，单张最大 20 MiB，合计最大 40 MiB。支持 PNG、JPEG、WebP，所有文件上传前按内容校验。路径有空格请加引号；不支持 GIF、URL 或 mask。原图不修改，结果另存新文件。
  • 参考图上传给所选 Provider，调用 multipart /v1/images/edits。Provider / 模型须支持相应的单图或多图编辑；模型列表存在不代表支持该接口。服务端仍可能拒绝格式、尺寸或能力。非兼容的 Responses 图片工具接口不在此功能范围。
  • 按健康/顺序选择一个 Provider；请求发出后不自动重试或向其他 Provider fallback。失败后先核实上游状态，再明确选择其他服务商重新运行。
  • 第一个参数是 Provider 名；第二个参数匹配模型缓存时作为具体模型，否则从第二个参数开始作为提示词并使用默认模型。
  • 命令执行前会自动刷新模型缓存；也可以先运行 ai status 检查。指定模型时建议给提示词加引号。
  • b64_json 默认以 0600 权限保存到当前工作目录并输出绝对路径；core 调用显式指定 outputDir 时保存到指定目录。远程响应只接受无凭证的 https URL。
  • 图片请求等待完整上游响应的默认期限为 10 分钟（600000 毫秒），可用正整数环境变量 AI_GATEWAY_IMAGE_TIMEOUT_MS 覆盖，覆盖响应头和响应体读取。
  • 每次请求前先在输出目录建立 .ai-image-recovery/<uuid>.json 待完成记录；完整响应在 usage 处理和图片提取前私密保存，目录/文件权限为 0700/0600。失败时报告记录路径；使用 ai image recover <response-file> 可在本地重新提取，不刷新 Provider、不调用 API、不产生费用。记录存在不表示图片已生成，未收到的响应无法恢复，也不保证进程退出后的上游结果可取回。
  • 请求经过 execution-scoped Transport Proxy，真实 usage 复用唯一 UsageObserver 账本。

运行规则

  • 正整数 level 组成自动切换链；level: 0 只允许显式使用，不进入自动候选。
  • 用 ai failover off 可一键关闭自动降级：之后只尝试选定（或默认 level: 1）的 Provider，失败即报错不切换；ai failover on 恢复，ai failover 查看状态。关闭时同时停用连续响应头超时熔断，不因已有熔断或健康错误缓存跳过所选 Provider，每次 CLI 重试均实际访问上游；单次请求仍有 45 秒超时限制。开关在新启动的 execution 中生效，已有会话需退出后重启。
  • 显式指定 Provider 时不会先刷新全部 Provider，而是直接使用该 Provider 的已缓存模型并实际尝试；健康缓存暂时为 error 不会在请求前静默跳过，失败后才进入同模型族的自动切换链。
  • Claude Code 只在提供 Claude 模型的 Provider 间切换；Codex 只在提供 Codex/OpenAI 兼容模型的 Provider 间切换，不跨模型族。
  • 只有会产生补全的模型端点（/v1/messages、/v1/chat/completions、/v1/completions、/v1/responses、/v1/embeddings、/v1/images/generations、/v1/images/edits）的带请求体 POST 参与降级：在产生有效输出前遇到连接错误、认证错误、限流或上游故障时，会在同一 Claude Code/Codex 会话内切换 Provider、改写备用模型并显示提示。multipart 参考图上传是例外，不自动重试或轮转。
  • CLI 启动期的无请求体 GET 探测，以及辅助端点（多数中转站未实现的 /v1/messages/count_tokens 等）的 404，都会原样返回给 CLI，既不触发 Provider 轮转，也不计入健康分。
  • 一次失败不会立刻换 Provider：限流（429）、5xx、连接层错误和有效输出前的流中断先在当前 Provider 原地重试（默认最多 2 次尝试，退避 300ms 起翻倍），重试额度用尽才轮转；401/403/404 与响应头超时是确定性失败，不重试直接换下一跳。重试成功不计失败、不扣健康分，重试全部失败整段只记一次失败。
  • 已经产生文字、推理或工具参数后不会静默重放；只有后续带请求体的模型 POST（不含 multipart）确认切换；GET、空请求及 count_tokens 不消耗待确认状态。
  • 真实成功的健康检查把该 Provider 的健康分直接恢复到满分，历史误判扣分不会长期滞留。
  • Claude Code 使用临时 --settings 注入环境变量，不修改用户 settings；本次子进程会移除继承的 ANTHROPIC_AUTH_TOKEN，临时 settings 还会用空值遮蔽用户 settings 里的同名变量，避免与所选 Provider 的 ANTHROPIC_API_KEY 形成双认证。
  • ai use codex 使用本次子进程的 -c model_provider=... 固定所选 provider，并通过 env_key = "OPENAI_API_KEY" 使用 AI Gateway 注入的 Key；不会修改 Codex 全局认证或配置。
  • provider 的 mode 为 auto 时，非 root 执行 Claude Code 会追加 --dangerously-skip-permissions；ask 模式不会追加，并会在启动前确认。root 下请求 auto 会被安全约束为默认权限，临时 settings 中继承的 bypass 配置也会被清除。
  • OpenAI 兼容地址用于 Codex 时会使用 /v1，用于 Claude 时会去掉 /v1。
  • Claude 与 Codex 通过唯一 execution-scoped 代理记录实际 provider/model、请求 traceId、sessionId 及已观测用量；默认账本为 usage.json，显式迁移后为 history.sqlite。Provider 返回的成本优先于价格表估算；写失败记录 usage_persistence_failed，不重放已完成请求。
  • 日志仅记录 SHA-256 Key 指纹，不含首末 Key 字符。会话保存最近成功 actualProvider/actualModel，Web 持久化终止事件支持逐请求耗时和观测用量；旧记录无关联时显示未知，侧栏仍代表默认 Provider。

--trace 同时匹配请求 traceId 与父执行 executionId，按时间排列完整日志文件中的匹配事件，不限最近 500 行。每个新代理请求有独立 traceId，并关联父执行和 sessionId；终止事件 openai_usage_proxy_request_settled 记录请求结果、耗时及落点。旧日志缺少关联或终止证据时保留未知，不按时间猜测；内网 API 的 x-request-id 响应头可用于反查该请求。

models 只对选中的 provider 调用 GET /models，刷新并列出完整模型目录，不调用推理端点、不产生推理 Token，也不覆盖已有真实健康状态。若 provider 不开放模型目录，models 会如实报告 404、451 等目录错误；这不代表缓存模型不可用，可改用 check 做最小真实验证。check 复用与 status 相同的真实验证规则，但只刷新一个 provider；省略名称时交互选择，提供名称时精确匹配，不会检查其他 provider。status 会刷新全部 provider 模型缓存，并从实际存在的 Claude/Codex 模型族中各选一个代表模型做真实调用验证；Codex 优先使用 Responses API。已通过手工模型验证但不开放模型目录的 provider 会使用缓存模型继续真实检查，不会因为 GET /models 返回 451 而直接判错。每次验证使用最短输入且输出上限为 1 token，不逐个验证全部模型，也不自动重试产生 Token 的请求。代表模型最多等待 30 秒；本地超时时上游仍可能已经处理成功，因此显示 unknown。验证返回的结构化 usage 会计入统一账本。

凭据与历史迁移

Provider 系统凭据库

ai secrets status
ai secrets migrate
ai secrets rollback --yes

ai secrets 等同 ai secrets status，仅显示后端、引用和明文数量，不输出 Key。migrate 显式启用保护；rollback --yes 将当前配置和快照的 Provider Key 导出为明文，用于迁移机器或兼容旧版本。

Provider 使用系统 Keychain、Credential Manager 或 Linux Secret Service；Linux 没有已解锁凭据服务时请继续使用受限权限的旧配置。迁移先写入、读回验证，再原子替换 providers.json 为 version=1、secretBackend=keyring 的 providers 文档。引用按当前用户及 AI_GATEWAY_HOME 路径隔离；移动目录、机器或降级前先安全导出。锁定、缺失或写入失败时不降级明文。轮换、旧快照恢复及删除全部后重建均保留保护方式。旧凭据版本不自动删除，以支持快照恢复；外部备份和磁盘历史不安全擦除。

迁移前停配置写入；Web 快照逐份转换，失败可能留下未迁移快照，用 secrets status 检查并重试，不承诺跨文件事务。仅迁移 Provider，不改 memory.json、Telegram Token、原生 auth.json、Claude settings 或临时认证文件。

用量与会话 SQLite 存储

ai history status
ai history migrate
ai history backup
ai history restore <backup.sqlite> --yes
ai history rollback --yes

ai history 等同 ai history status。先 migrate 启用 SQLite，再用 backup 创建备份；restore 只接受 history-backups/ 内备份路径的文件名（如 xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx.sqlite），不传完整路径。恢复覆盖备份后的历史；rollback --yes 导出最新 JSON 后停用 SQLite。历史备份不恢复配置、授权计数、Telegram 或记忆数据库。

历史迁移、恢复和回滚前停止所有 Runtime CLI/API/Web/Bot 写入，不混用旧版本。迁移后 history.sqlite 是唯一权威，usage.json/sessions.json 不双写；损坏、版本未知或启用标记存在但数据库丢失时失败关闭，doctor --fix 不重置数据库。SQLite backup API 生成受限权限副本；恢复先校验并保留当前数据库，覆盖备份后的历史；回滚先导出最新 JSON 再停用数据库。history-storage.json 记录启用状态，不属于 Web 配置快照。

SQLite 用量/会话按索引分页。日志分页扫描文件但仅保留当前页；最近日志从尾部分块读取，忽略无效行及大于 4 MiB 的单条记录。ai log --print --trace 同时关联请求与父 executionId。总览和完整调用聚合仍扫描相应历史；日志轮转、长期容量与目标平台服务验收仍需部署者完成。
